把旧手机变成小服务器：刷机与搭建全记录

Redmi Note 2（hermes / MT6795）· MIUI 9 → LineageOS 14.1 → Termux 服务器 · 2026-10-17

0概览

目标：一台常年插电、能上网、屏幕正常显示的局域网小服务器。最终效果：

远程登录ssh -p 8022 192.168.43.247（Termux，密钥登录）

文中标记

每段命令前的标签说明它在哪里执行： MAC 在 Mac 终端执行； ADB 通过 adb shell 在手机系统里执行； TWRP 手机处于 TWRP 恢复模式时，通过 adb 执行； TERMUX 在手机 Termux 里（或 SSH 登录后）执行。

1准备工作

1.1 Mac 端工具

MAC 
which adb fastboot      # 确认 Android 调试工具已安装
adb devices -l          # 列出已连接、已授权的手机
  • adb：Android 调试桥，用来在手机上执行命令、传文件、重启到不同模式。
  • fastboot：bootloader 模式下刷写分区的工具。两者都来自 Android SDK Platform-Tools。
  • -l：显示详细信息（型号、代号），用来确认连的是哪台设备。

另外用到：ffmpeg（图片 / 音频转换）、yt-dlp（下载音乐）、python3。

1.2 手机端设置

  1. 设置 → 关于手机 → 连续点"MIUI 版本"7 次，打开开发者模式。
  2. 设置 → 其他设置 → 开发者选项 → 打开 USB 调试。
  3. 用数据线连接 Mac，手机弹出"允许 USB 调试吗？"时勾选"始终允许"。

1.3 USB 连不上怎么排查

MAC 
ioreg -p IOUSB -l -w0 | grep -E '"USB Product Name"|"idVendor"'
  • 列出 Mac 识别到的所有 USB 设备。小米手机的厂商号 idVendor 是 10007（0x2717），联发科是 3725（0x0e8d）。
  • 如果这里都看不到手机，问题在物理层（线或接口），跟 adb 无关。
实际遇到的坑：前几根线都是"只能充电"的线。有一次插的是带耳机口的转换头，Mac 只认出了转换头里的 Hub 和声卡芯片（AB13X USB Audio），手机信号根本没过来。最后换成一根能传数据的直连线才识别出来。

2读取手机信息、确认 bootloader

ADB 
adb shell getprop ro.product.device           # 设备代号，必须是 hermes
adb shell getprop ro.build.version.release    # Android 版本：5.0.2
adb shell getprop ro.build.version.incremental # MIUI 版本：V9.6.1.0.LHMCNFD
adb shell getprop ro.board.platform           # 芯片平台：mt6795
adb shell dumpsys battery                     # 电量、电池健康
  • getprop：读取 Android 系统属性。代号最重要：刷机包只能用对应代号（hermes）的，Redmi 2（wt88047）的包不能混用。
  • dumpsys battery：刷机前确认电量充足（建议 > 50%），刷到一半没电容易出事。
MAC 
adb reboot bootloader            # 重启进 fastboot（屏幕出现兔子）
fastboot getvar all              # 读取 bootloader 状态
  • 输出里 unlocked: yes、secure: no 表示 bootloader 已经解锁，可以直接刷，不用走小米官方解锁流程。
  • 手动进 fastboot：关机后同时按住 音量下 + 电源。
注意：这台机器不支持 fastboot boot twrp.img（临时启动、不写入），返回 unknown command。所以 TWRP 只能直接刷进 recovery 分区。

4刷入 TWRP

MAC 
adb reboot bootloader
fastboot flash recovery twrp-3.7.0_9-0-hermes.img   # 只写 recovery 分区，系统和数据不动
  • flash recovery：把镜像写进 recovery 分区，替换小米自带的恢复模式。
坑：MIUI 会覆盖 TWRP。第一次刷完，手机开进了 MIUI，MIUI 开机时自动把 recovery 还原成原厂（菜单里有"将 update.zip 安装至系统"）。
解决：刷完 不要让它开进 MIUI，直接用按键进 TWRP：
  1. 在 fastboot（兔子）界面重新执行 fastboot flash recovery …。
  2. 在兔子界面 同时按住 音量上 + 电源，约 10 秒后强制重启。
  3. 看到 Mi 标志后 只松开电源，继续按住音量上，直到出现 TWRP。
  4. TWRP 问是否保持 system 只读时 向右滑动允许修改。TWRP 会修补系统，以后就不会再被覆盖。
TWRP 
adb devices -l          # 状态应为 recovery，product:cm_hermes

5完整备份（救砖用）

MTK 手机刷坏最怕丢 IMEI（存在 nvram / protect1 / protect2 分区）。所以在动系统之前，先把 除个人数据和缓存以外的所有分区 原样复制到 Mac。

TWRP 
ls -l /dev/block/platform/mtk-msdc.0/by-name/      # 查看分区名 → 块设备的对应关系

B=/Volumes/SSD1G/download/redmi-note2-flash/backup-miui9-$(date +%Y%m%d); mkdir -p $B; cd $B
for p in proinfo nvram protect1 protect2 seccfg lk boot recovery secro para logo \
         expdb tee1 tee2 flashinfo system; do
  adb exec-out "dd if=/dev/block/platform/mtk-msdc.0/by-name/$p bs=1M 2>/dev/null" > $p.img
  echo "$p  手机:$(adb shell "dd if=/dev/block/platform/mtk-msdc.0/by-name/$p bs=1M 2>/dev/null | md5sum" | cut -c1-12)  Mac:$(md5 -q $p.img | cut -c1-12)"
done
# 预加载器（preloader）不在 by-name 里，单独备份
for p in mmcblk0boot0 mmcblk0boot1; do adb exec-out "dd if=/dev/block/$p bs=1M 2>/dev/null" > $p.img; done
  • dd if=… bs=1M：按 1 MB 块原样读出整个分区，连空白区域一起复制，属于"位对位"备份。
  • adb exec-out：把手机上命令的二进制输出直接传到 Mac 文件。adb shell 可能会改换行符，传二进制必须用 exec-out。
  • 每个分区都比较手机端和 Mac 端的 md5，一致才算备份成功。实际结果是 18 个分区全部一致，共 2.2 GB。
  • 不备份 userdata（12 GB 个人数据，用户已自行处理）和 cache。

6清除并刷入 LineageOS

这个 TWRP 版本没有带命令行工具 twrp，所以清除和安装都是手动完成的，效果和在 TWRP 界面上点按钮一样。

6.1 清除旧数据（保留内部存储）

TWRP 
adb shell
mount -t ext4 /dev/block/platform/mtk-msdc.0/by-name/userdata /data
cd /data && for f in * .[!.]*; do [ "$f" = media ] || rm -rf "$f"; done   # 删掉 media 以外的全部
mke2fs -t ext4 -F /dev/block/platform/mtk-msdc.0/by-name/cache             # 格式化 cache
mkdir -p /cache && mount -t ext4 /dev/block/platform/mtk-msdc.0/by-name/cache /cache
  • MIUI 的应用数据和 LineageOS 不兼容，必须清掉；/data/media 是内部存储（照片等），保留。
  • mke2fs -t ext4 -F：把 cache 重新格式化为 ext4，-F 表示强制执行。
  • cache 必须挂载：安装程序会在 /cache/recovery/ 里放临时文件。
坑：E1001 Failed to update system image。第一次用 make_ext4fs 格式化 cache 实际没成功（输出 "Total bytes: 0"），cache 也没挂载，导致安装中途失败。改用 mke2fs 格式化并挂载后，第二次安装成功。

6.2 安装刷机包

MAC 
adb push lineage-14.1-20180913-UNOFFICIAL-hermes.zip /data/media/0/   # 传到内部存储
adb shell md5sum /data/media/0/lineage-14.1-*.zip                     # 和 Mac 上的 md5 比对
TWRP 
cd /tmp && unzip -o /data/media/0/lineage-14.1-*.zip META-INF/com/google/android/update-binary
chmod 755 /tmp/META-INF/com/google/android/update-binary
/tmp/META-INF/com/google/android/update-binary 3 1 /data/media/0/lineage-14.1-20180913-UNOFFICIAL-hermes.zip
echo "EXIT=$?"          # 0 表示成功
  • update-binary：每个刷机包都自带的安装程序。TWRP 点"安装"时，其实也是在运行它。
  • 参数 3 1 <zip>：3 是 recovery 接口版本，1 表示把进度信息输出到标准输出（文件描述符 1），最后是刷机包路径。
  • 安装脚本做的事：检查机型 → 整个重写 system 分区（约 1 GB）→ 写入新的 boot。
TWRP 
mount -o ro /dev/block/platform/mtk-msdc.0/by-name/system /system
grep -E "ro.build.version.release|ro.cm.version" /system/build.prop   # 应为 7.1.2 / 14.1-…
umount /system; sync; reboot

首次开机约 2 分钟。

7首次开机检查

ADB 
adb shell getprop sys.boot_completed     # 1 = 开机完成
adb shell getprop gsm.version.baseband   # 有值说明通信模块（基带）正常
adb shell service call iphonesubinfo 1   # 读取 IMEI（UTF-16 编码，需要解码）
  • service call iphonesubinfo 1 返回的是 Parcel 原始数据，每个 32 位字里有两个字符，而且顺序是反的。比如 00360038 应该读作 "86"。解码后再用 Luhn 算法验证校验位，确认 IMEI 完好（实测通过）。

7.1 打开 adb root 权限

ADB 
adb shell setprop persist.sys.root_access 3   # 3 = 应用和 adb 都可获得 root
adb root                                      # adbd 以 root 身份重启
  • LineageOS 默认关闭 adb root。后面读写分区、修改系统文件都需要 root。
  • 每次重启后 adbd 默认回到普通权限，需要时再执行一次 adb root。

7.2 连接 Wi-Fi（命令行）

ADB 
printf 'network={\n\tssid="Redmi7"\n\tpsk="热点密码"\n\tkey_mgmt=WPA-PSK\n}\n' \
  | adb shell 'cat >> /data/misc/wifi/wpa_supplicant.conf'
adb shell 'chown wifi:wifi /data/misc/wifi/wpa_supplicant.conf; svc wifi disable; svc wifi enable'
  • 把热点配置追加到 Android 的 Wi-Fi 配置文件，然后用 svc wifi 重启 Wi-Fi 让它生效。
  • 实际操作时密码是直接从 Orange Pi 的网络配置里读出、通过管道写进手机的，没有出现在命令或日志里。

8安装 Termux 与 SSH

MAC 
curl -fLO https://f-droid.org/repo/com.termux_1002.apk        # Termux 0.118.3
curl -fLO https://f-droid.org/repo/com.termux.boot_1000.apk   # Termux:Boot 0.8.1
adb install -r com.termux_1002.apk
adb install -r com.termux.boot_1000.apk
adb shell 'dumpsys package com.termux | grep userId=; dumpsys package com.termux.boot | grep userId='
  • 必须从 F-Droid 下载，并且两个都来自同一来源：插件和主程序共用一个 sharedUserId，签名不一致的话第二个装不上。两个 userId 都是 10063，说明签名一致。
  • 新版 Termux 要求 Android 7 及以上，这也是选择 LineageOS 14.1 的原因。
ADB 
adb shell settings put global stay_on_while_plugged_in 3   # 插着 USB 或充电器时屏幕常亮
adb shell dumpsys deviceidle whitelist +com.termux          # 不让省电模式限制 Termux
adb shell am start -n com.termux/.app.TermuxActivity        # 首次打开，解压基础环境
  • stay_on_while_plugged_in 3：1 = 交流电，2 = USB，3 = 两者都算。
  • deviceidle whitelist：Doze 省电白名单。

8.1 SSH 密钥登录

MAC 
H=/data/data/com.termux/files/home
cat ~/.ssh/id_ed25519.pub | adb shell "mkdir -p $H/.ssh && cat > $H/.ssh/authorized_keys"
adb shell "chmod 700 $H/.ssh; chmod 600 $H/.ssh/authorized_keys; chown -R u0_a63:u0_a63 $H/.ssh"
TERMUX 
pkg update -y && pkg install -y openssh python jq neofetch procps   # 安装软件包
sshd                                                                 # 启动 SSH 服务，端口 8022
MAC 
ssh -p 8022 192.168.43.247      # 用户名可以随便写，Termux 只认密钥
  • Termux 是普通应用，不能使用 1024 以下的端口，所以 SSH 用 8022。
  • u0_a63（uid 10063）是 Termux 的用户，以 root 身份写入的文件要把所有者改回它。
坑：Termux:API 在这个 ROM 上用不了。系统组件依赖开机时设置的 LD_PRELOAD，Termux 用自己的值覆盖了它，导致报 cannot locate symbol "__xlog_buf_printf"。fastfetch 也是同样的原因，所以改用纯 bash 写的 neofetch。普通应用读不到的信息（Wi-Fi 名称等）改由 root 服务来读，见第 9 节。

9后台服务（init 守护）

工程 ~/ai_claude/redmi-note2-server 里有三个系统服务，都放在 /system/etc/init/，由 Android 的 init 进程在开机时启动：

服务身份作用
phonectlroot充电限制 40–70%；每 15 秒把 Wi-Fi、IP、充电状态写入 ~/.phonestat.json
termux-servicesuid 10063守护 sshd 和网页服务，挂了 30 秒内拉起；持有唤醒锁
termux-introroot，开机执行一次开机完成后把 Termux 全屏打开并运行演示

9.1 服务定义示例

# system/termux-services.rc
service termux-services /system/bin/sh /system/bin/termux-services.sh
    class late_start          # 在系统主要服务之后启动
    user 10063                # 以 Termux 用户运行（必须写数字）
    group 10063 inet wakelock # inet = 允许联网，wakelock = 允许持有唤醒锁
# system/termux-intro.rc
service termux-intro /system/bin/sh /system/bin/termux-intro.sh
    user root
    oneshot                   # 只运行一次，不自动重启
    disabled                  # 不随 class 启动，由下面的触发器启动
on property:sys.boot_completed=1
    start termux-intro

9.2 部署

MAC 
cd ~/ai_claude/redmi-note2-server
./deploy.sh system     # 推送三个系统服务（需要 USB + adb root），下次开机生效
./deploy.sh web        # 通过 SSH 推送网页服务、开机脚本、Termux 设置
./deploy.sh all        # 两者都做

deploy.sh system 内部做的事：adb root → mount -o rw,remount /system（把系统分区改成可写）→ adb push 脚本和 .rc 文件 → chmod/chown → restorecon（恢复 SELinux 标签）。

坑 1：Termux:Boot 不可靠。一开始用 Termux:Boot 开机启动 sshd，结果凌晨 3 点 SSH 和网页一起断了。日志显示 ActivityManager: Killing com.termux: empty for 2049s：Termux 应用闲置约 35 分钟后被系统当作空进程结束，它下面的子进程也跟着被杀。
解决：改由 init 直接以 Termux 用户身份守护，不受应用清理机制影响。
坑 2：init 不认 u0_a63。写 user u0_a63 时服务不停重启，退出码 127：Android 7 的 init 无法解析应用用户名，切换用户失败。改成数字 10063 后正常。
坑 3：pgrep -x sshd 永远找不到。在这个内核上，进程名被记录为被截断的路径 /data/data/com.，而不是 sshd。改为按完整路径匹配：pgrep -f "^$PREFIX/bin/sshd"。

10状态网页

termux/webstat/server.py（只用 Python 标准库）+ index.html，监听 0.0.0.0:8080，局域网里任何设备都能打开。

地址内容
/网页面板，每 5 秒刷新，深色或浅色跟随系统
/api/status当前数据（JSON）
/api/history最近 24 小时，每分钟一个采样点
MAC 
curl -s http://192.168.43.247:8080/api/status | jq .battery   # 在 Mac 上直接查电池

数据来源：/sys/class/power_supply/battery/*（电池）、/sys/class/thermal/thermal_zone*（温度）、/proc/stat（CPU）、/proc/meminfo（内存）、/proc/net/dev（流量），以及 root 服务写出的 ~/.phonestat.json（Wi-Fi 名称、IP、充电控制状态）。

坑：CPU 使用率显示 50%，实际只有约 8%。原因有两个：① 联发科内核的 iowait 计数器是坏的（会出现负数或天文数字）；② 原来在请求网页时才测量，量到的主要是网页服务自己的开销。
解决：计算时去掉 iowait，并改为后台线程固定每 5 秒采样一次。负载（load average）在这个内核上空闲时也显示约 15，网页上已标注"仅供参考"。

11充电限制 40–70%

常年插电时，这块 2015 年的电池一直满电容易鼓包。phonectl 让电量到 60% 时停止充电，降到 50% 时恢复充电。40–70% 的窄区间充放电深度很浅，停电时还有一半电量，相当于一个小 UPS。

ADB 
echo "0 1" > /proc/mtk_battery_cmd/current_cmd   # 停止充电
echo "0 0" > /proc/mtk_battery_cmd/current_cmd   # 恢复充电
cat /sys/class/power_supply/battery/capacity     # 当前电量（这个可以读）
  • 格式 "A B"：A 是"USB 电流不限制"开关，B 是强制放电开关（1 = 停止充电）。这个格式来自 hermes 内核源码 drivers/power/mediatek/battery_common.c。
  • /sys/devices/platform/battery/ChargerEnable 看起来像充电开关，但实际不起作用，不要用。
大坑：千万不要读取 current_cmd。这个驱动的"读取"函数里写着 cmd_discharging = 1，只要执行一次 cat current_cmd 就会停止充电。调试时就是这样误触发的，手机一度没在充电。
为什么从 50–60% 改成了 40–70%：实测发现，联发科的"停止充电"会把整个充电电路断开，手机改吃电池，不像骁龙那样改由 USB 直接供电。区间太窄时，手机一天要在 60% 和 50% 之间来回约 22 次，相当于每天 2 次完整充放电，损耗反而更大。
也试过用温控里的充电限流（/proc/driver/thermal/clbcct + 冷却设备 mtk-cl-bcct00，限流值要写 1，写 0 会被忽略），希望做到电源直通。但系统温控每 5 秒检查一次，不到 1 秒就把它关回去了，除非修改温控绑定。电池温控上还挂着 60°C 过热关机保护，所以没有采用这个办法。

修改区间：在手机上创建 /data/local/phonectl.conf，写入 CHARGE_LOW=40、CHARGE_HIGH=60，然后重启。日志在 /data/local/phonectl.log。

12开机第一屏（logo 分区）

开机最先出现的那张图（原来的 "mi"）由 bootloader 从 logo 分区读取，不是普通的图片文件。

12.1 logo 分区格式

位置内容
0–511 字节MTK 分区头：魔数 0x58881688、数据长度、名称 "LOGO"
之后图片数量（39）、总长度、每张图的偏移
图片数据每张都是 zlib 压缩的原始像素，全屏图为 1080×1920、BGRA 格式
第 0 张fastboot 兔子
第 1 张关机充电背景（星空）
第 2 张 / 第 38 张开机第一屏：bootloader 显示一次，内核再显示一次，两处都要换

12.2 生成并写入

MAC 
cd ~/ai_claude/redmi-note2-server
B=/Volumes/SSD1G/download/redmi-note2-flash
python3 tools/build_logo.py $B/backup-miui9-20261017/logo.img assets/images/boot-logo-v2-android.png logo-new.img --colors 64
  • 第 1 个参数：原厂 logo 备份，用来提供其余 37 张图和分区头。
  • --colors 64：把图片减到 64 色来压缩体积。黑底文字类的图 12 色就够了；带光晕渐变的图用 64 色，避免出现一圈圈色带。
  • 脚本默认把第 1 张充电背景换成纯黑来腾出空间，加 --keep-charging-bg 可以保留原图。
  • 脚本最后会提示总大小是否在原厂大小（1.85 MB）以内。
ADB 
adb root
adb push logo-new.img /data/local/tmp/l.img
adb shell 'dd if=/data/local/tmp/l.img of=/dev/block/platform/mtk-msdc.0/11230000.MSDC0/by-name/logo bs=1048576; sync'
adb shell 'dd if=/dev/block/platform/mtk-msdc.0/11230000.MSDC0/by-name/logo bs=1048576 | md5sum'   # 和 Mac 上的 md5 比对
  • 在 LineageOS 下，分区路径多了一层 11230000.MSDC0，和 TWRP 下的路径不一样。
  • 写入后读回来校验 md5，一致再重启。
坑：第一屏变成黑屏。第一版 logo 有 4.8 MB（原厂只有 1.8 MB），图片细节多、压缩率低，又要存两份。bootloader 读取 logo 的空间有限，读不完整就显示黑屏，而开机动画由系统读取，不受这个限制。
解决：减少颜色数 + 充电背景换成纯黑，总大小降到原厂以内，第一屏恢复正常。

13开机动画与声音

第二个画面是 /system/media/bootanimation.zip，结构如下：

bootanimation.zip           # 必须"仅存储"，不能压缩（zip -0）
├── desc.txt
├── part0/  00000.jpg … 00057.jpg   audio.wav
└── part1/  00000.jpg
# desc.txt
1080 1920 5      # 宽 高 帧率（每秒 5 帧）
c 1 0 part0      # c = 必须完整播放；1 = 播放一次；0 = 结尾不停顿
p 0 0 part1      # p = 系统一就绪就可以中断；0 = 无限循环
  • part0：前 45 帧是进度条从 0 走到 100%（9 秒，先快后慢），之后若干帧停在 100%，补到和声音一样长。
  • audio.wav：放在 part0 里，和 part0 同时开始播放，格式为 16 位 PCM。
  • c 是关键：即使系统已经准备好，也要等 part0 完整播放完才进入桌面，所以声音不会被截断。
MAC 
tools/build_bootanim.sh assets/images/bootanim-v2-portrait.png bootanimation.zip assets/audio/phone_boot.mp3
ADB 
adb root
adb shell 'mount -o rw,remount /system'
adb push bootanimation.zip /system/media/bootanimation.zip
adb shell 'chmod 644 /system/media/bootanimation.zip; restorecon /system/media/bootanimation.zip; sync'
ADB 
# 重启后确认声音完整播放
adb shell 'logcat -d | grep -E "found audio.wav|audioplay: (playClip|destroying)"'
坑：声音没放完就进了桌面。开机时音频服务初始化要约 3 秒，画面也会等它，声音和画面同时开始；但原来 part0 只有 9 秒，声音 11 秒，系统一就绪动画就关了。
解决：part0 补帧，延长到"声音时长 + 0.4 秒"。实测声音完整播放 11.5 秒，系统其实在第 7.8 秒就准备好了。代价是开机慢约 3–4 秒。
音乐素材：用 yt-dlp --no-playlist -x --audio-format mp3 --audio-quality 320K -o "%(title).60s [%(id)s].%(ext)s" <链接> 下载。--no-playlist 只下当前视频，--audio-quality 320K 保证 320kbps（用 --postprocessor-args 指定码率对 webm 音源无效）。用 Audacity 剪成 8–11 秒最合适。

14开机 Termux 演示

进入桌面 3 秒后，termux-intro 把 Termux 全屏打开，运行 ~/bin/boot-intro，整个过程约 15 秒：

  1. 逐字"敲出"并执行：neofetch、uptime、ping、df、free。
  2. ai-link --all：真实连接 Claude、Gemini、OpenAI 三家的 API 服务器，显示 DNS、TCP、TLS 耗时。不带任何密钥，返回 401/403 就说明服务器在线、网络通。
  3. status：7 项实时状态面板，全部正常时显示 ▶ ALL SYSTEMS NORMAL，有异常时如实显示项数。
  4. 最后停在命令行，可以直接操作。
ADB 
# termux-intro.sh 的核心：通过 Termux 的命令接口，在前台新开一个会话
wm dismiss-keyguard
am startservice --user 0 -n com.termux/com.termux.app.RunCommandService \
  -a com.termux.RUN_COMMAND \
  --es com.termux.RUN_COMMAND_PATH /data/data/com.termux/files/home/bin/boot-intro \
  --ez com.termux.RUN_COMMAND_BACKGROUND false
am start --user 0 -n com.termux/.app.TermuxActivity
  • RUN_COMMAND：Termux 提供给外部调用的命令接口，需要在 ~/.termux/termux.properties 里开启 allow-external-apps = true。
  • RUN_COMMAND_BACKGROUND false：在前台新建一个看得见的终端会话，而不是在后台静默执行。
  • wm dismiss-keyguard：解除锁屏，作为保险。
